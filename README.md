# E90 Пульт — SMS-пульт для StarLine E90 GSM

Android-приложение: управляет сигнализацией StarLine E90 (GSM-модуль старого поколения, ПО I7) и показывает её состояние **только через SMS** — без сервера StarLine и без интернета. Интернет нужен лишь для необязательного запроса координат соты в OpenCellID.

Неофициальное приложение, к компании StarLine отношения не имеет.

---

## Что проверено, а что нет

**Проверено на машине (из ТЗ):** только две команды:
- `09` — версия ПО и статус;
- `00551` — уровень сигнала и статус связи с сервером.

**Не проверено** (взято из документации StarLine, в приложении помечено «не проверено»):
- все остальные команды таблицы;
- запрос баланса через модуль (`*100#`) — в инструкции описан для ПО Q2 и новее;
- формат ответа на `41`, SMS о ходе обновления ПО, тревожные SMS — образцов нет, они сохраняются и показываются как есть;
- состояние двигателя — определяется только по явным словам в ответе («двигатель запущен/заглушен»);
- продление работы двигателя повторной `21` — по документации появилось в ПО L3;
- команды `21XX#`, `37`, `0093` — по документации неприменимы к E90 (нужен другой центральный блок или модуль), показаны неактивными.

**Как проверялся сам код.** В среде разработки нет доступа к репозиториям Gradle и Google Maven, поэтому **полная сборка `gradlew assembleDebug` здесь не запускалась**. Сделано вместо неё:
- весь код компилируется компилятором Kotlin 2.1.0 (той же версии, что в проекте) с плагином Compose против настоящего `android.jar` API 35, ошибок нет; проверки Compose (вызовы @Composable вне контекста, try/catch и т. п.) пройдены. Библиотеки AndroidX здесь недоступны, поэтому вместо них — заглушки с теми же сигнатурами;
- имена и типы параметров всех использованных функций Compose, Material3 и Activity в этих заглушках сверены с официальными описаниями API AndroidX;
- все 41 SQL-запрос Room проверены на SQLite по схеме сущностей, параметры запросов совпадают с параметрами функций;
- все XML-ресурсы проверены на корректность, атрибуты и стили — по API 35;
- 41 модульный тест (разбор ответов, в том числе склеенных без пробелов, версии, сборка текста команд, CSV, баланс, таблица команд, привязка ответов) проходит;
- логика защиты (повтор команд, удержание кнопки, ПИН, движение, виджет, привязка ответов) дополнительно проверена отдельным разбором кода, найденные недочёты исправлены.

Если при первой сборке что-то не соберётся — пришлите текст ошибки.

## Сборка и установка

Нужны Android Studio (любая актуальная) **или** JDK 17+ и Android SDK с платформой 35. При первой сборке Gradle скачает себя (8.11.1) и зависимости — нужен интернет.

### Вариант 1. Android Studio
Откройте папку проекта (`File → Open`), дождитесь синхронизации, затем `Build → Build App Bundle(s) / APK(s) → Build APK(s)`.

### Вариант 2. Командная строка (Windows, PowerShell в папке проекта)
Пути ниже — стандартные для Android Studio; если у вас другие, поправьте.

```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
.\gradlew.bat assembleDebug
adb install -r app\build\outputs\apk\debug\app-debug.apk
# конец
```

`adb` лежит в `%LOCALAPPDATA%\Android\Sdk\platform-tools`. Телефон — с включённой отладкой по USB.

### Linux / macOS (терминал в папке проекта)

```bash
chmod +x gradlew
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
# конец
```

Готовый APK: `app/build/outputs/apk/debug/app-debug.apk`. Release-сборка (`assembleRelease`) подписывается отладочным ключом — для ручной установки этого достаточно.

### Вариант 3. Сборка на GitHub
В проекте есть `.github/workflows/build-apk.yml`: при каждом push в ветку `e90pult` GitHub собирает APK, прогоняет модульные тесты и lint. APK и журналы появляются в разделе Releases как черновики — их видит только владелец репозитория.

Все сборки подписываются одним постоянным ключом. Он создаётся при первой сборке и хранится в черновике релиза «Ключ подписи APK». Не удаляйте и не публикуйте этот черновик: без ключа новую версию не поставить поверх установленной, придётся удалять приложение вместе с данными. Если собираете и на своём ПК, положите этот файл в `%USERPROFILE%\.android\debug.keystore` — тогда подпись у всех сборок будет одинаковой. Если там уже лежит ключ других проектов, сначала сохраните его копию: файл заменится.

## Первый запуск

1. **Разрешения.** Приложение спросит их с объяснением:
   - SMS (отправка, приём, чтение входящих) — команды и ответы; чтение — чтобы не терять ответы, пришедшие, пока приложение было выгружено;
   - состояние телефона — выбор SIM для отправки;
   - уведомления — тревоги, ответы, «нет ответа».
2. **Номер сигнализации.** Введите номер SIM, которая стоит в сигнализации (МегаФон), и выберите SIM телефона для отправки. Номер этой SIM должен быть записан в модуль как M1.
3. **Проверка.** Нажмите «Отправить 09» и дождитесь ответа (версия ПО, GSM, АКБ, сота). При слабом сигнале ответ может идти несколько минут.

Можно пропустить настройку и включить «Режим отладки без машины» (эмулятор).

Остальные разрешения запрашиваются при первой нужде:
- геолокация — защита в движении (скорость по GPS);
- Bluetooth — выбор магнитолы машины;
- биометрия — вход в «Критичное» по отпечатку (Android 9+).

На Xiaomi, Huawei и подобных разрешите автозапуск и снимите ограничения батареи: иначе система может не будить приложение при входящих SMS. Кнопка «Настройки экономии батареи» — в «Настройках».

## Возможности

### Главный экран
Плитки: «Охрана» (11), «Снять» (10), «Запуск» (21), «Стоп» (20), «Статус» (09), «Связь» (00551), «Состояние» (41), «Баланс» (`*100#`).
- Управляющие команды отправляются после короткого подтверждения.
- Недоступная команда показывается серой; по нажатию приложение объясняет причину.
- Повторное нажатие той же команды в течение 3 секунд игнорируется.
- Смена машины (профиля) — с подтверждением, в движении недоступна.
- Выше плиток — карточка охраны и двигателя со временем последнего SMS и плашки: эмуляция, движение, новые функции ПО, ожидающие ответа команды.

### Отправка и ответы
- Отправка идёт через `SmsManager` выбранной SIM.
- Статусы: отправлено → доставлено оператором → ответ получен / нет ответа за N минут (N в настройках, по умолчанию 5).
- Ответ привязывается к самой ранней ожидающей команде, в окно которой пришёл. Ответ, пришедший вовремя, но найденный только при досканировании входящих, тоже привязывается к своей команде — «нет ответа» снимается.
- SMS от сигнализации без отправленной команды — «событие/тревога» с уведомлением высокого приоритета. Если до него была команда без ответа, к событию добавляется пометка «возможно, поздний ответ».
- SMS со словами «тревога» или «сработка» всегда дают уведомление высокого приоритета, даже если пришли в окне ожидания ответа на команду.
- Управляющие команды автоматически **не** переотправляются. Повтор — только кнопкой «Отправить ещё раз (вручную)» с подтверждением. Для 21 — отдельное предупреждение: модуль с ПО до K9 не отбрасывает старые SMS, и задержанная у оператора команда выполнится, когда дойдёт.
- Опасные, критичные команды и команды с параметрами повторяются только через полное окно команды — с ПИН-кодом, вводом кода, удержанием и проверкой движения. Эмулированную отправку настоящим SMS повторить нельзя.
- Каждое SMS сохраняется целиком. Неизвестные поля показываются «сырым» текстом.
- Многочастные SMS склеиваются; номера нормализуются (+7 / 8 / без кода).
- При запуске приложения входящие за сутки досканируются из базы SMS (без дублей).

### Статус автомобиля
- Охрана, замки, двигатель, напряжение АКБ, уровень GSM, связь с сервером, версия ПО — у каждого значения своё время получения.
- Цвет уровня GSM: меньше 15 — красный, 15–20 — жёлтый, больше 20 — зелёный.
- Буква связи: T — связь с сервером есть; G — интернет есть, модуль не зарегистрирован на сервере; A — идёт подключение; «-» — нет GPRS.

### Журнал и CSV
Фильтры: все, отправленные, полученные, события. Экспорт в CSV под русский Excel:
- разделитель «;», десятичная запятая;
- UTF-8 с BOM, переводы строк CRLF;
- даты в формате ДД.ММ.ГГГГ, время — отдельным столбцом;
- значения с «;», кавычками и переводами строк — в двойных кавычках;
- номера телефонов, коды с ведущими нулями, LAC/CI — в виде `="…"`, чтобы Excel не превращал их в числа или даты.

### Графики, местоположение
- Графики напряжения АКБ и уровня GSM за 24 часа, 7 дней, 30 дней или всё время.
- Местоположение по соте: LAC и CI (hex и десятичные).
- Необязательно — координаты из OpenCellID: ваш API-токен задаётся в настройках, результат помечен «приблизительно». Есть кнопки «Открыть в картах» и «OpenStreetMap».

### Баланс SIM сигнализации
- «Запросить баланс» отправляет модулю USSD-текст из профиля (по умолчанию `*100#`). Модуль сам выполняет запрос и присылает ответ оператора. **На ПО I7 не проверено.**
- Сумма берётся после слова «баланс». Если его нет — сумма с «р/руб/₽», но только в ответе на запрос баланса.
- Оценка текущего баланса: последний известный баланс, минус SMS, отправленные модулем после него (каждая часть отдельно, включая сам ответ с балансом), минус абонплата за прошедшие дни, минус трафик в сутки, плюс пополнения.
- Цену SMS, абонплату, трафик, порог предупреждения и срок напоминания задаёте вы.
- Можно ввести пополнение или текущий баланс вручную.
- Если оценка ниже порога — уведомление, не чаще раза в день. Если баланс давно не проверяли — напоминание.

### ПО модуля и новые функции
- У каждой команды в таблице — минимальная версия ПО модуля. Команды новых версий неактивны, пока ответ на 09 не покажет нужную версию; затем включаются сами, и приложение покажет, что появилось.
- Сравнение версий — «буква + цифра»: I7 < M8 < P5 < Q2.
- Разбор понимает расширенный ответ на 09 (код модуля, IMEI) и формат `VER:HD03-R5`.
- Требования к центральному блоку показываются подсказкой. Команды, неприменимые к E90, помечены.
- Мастер обновления `00591` — только на стоянке, при снятой охране и через «Критичное». Он предупреждает о слабом GSM и ведёт сеанс 30 минут: SMS о ходе обновления, приветствие с новой версией, версии до и после. Приветствие и SMS об обновлении в это время относятся к 00591, даже если ждёт ответа другая команда (например, 09).
- По базе знаний StarLine версии с P5 и новее выходили только для модулей HB03, FG63 и более новых. Потолок вашего модуля модуль сам назовёт в SMS о ходе обновления.

### Защита критичных настроек
Раздел **«Критичное»**:
- антиограбление (31);
- запись и удаление номеров M1–M4, новые пароли PW/PS;
- пароль даже для M1 (0096/0097), управление только с M-номеров;
- сбросы, экстренная перезапись M1 (9900);
- обновление ПО (00591), пересылка SMS (0069X);
- настройки профиля: номер сигнализации, SIM, пароль, Bluetooth машины, правка таблицы команд, удаление профиля.

Как защищено:
- **Вход** — по ПИН-коду приложения (хранится как PBKDF2-хеш) или отпечатку. Доступ открыт на 5 минут или до ухода приложения с экрана. После 5 неверных ПИН подряд — пауза 30 секунд, каждая следующая ошибка удваивает её (до часа); счётчик сохраняется и после перезапуска приложения.
- **Подтверждение** критичной команды — ввод её кода и удержание кнопки 3 секунды. Опасные команды из «Сервиса» — удержание 2 секунды. Если во время удержания условия изменились (машина тронулась, доступ закрылся), команда не уходит.
- **В движении недоступно**: «Критичное» и плитка «Стоп». Движение определяется по скорости GPS телефона выше порога (по умолчанию 10 км/ч) и по подключению телефона к Bluetooth-устройству машины (магнитоле); учитываются устройства из всех профилей. GPS работает только пока приложение на экране; координаты никуда не отправляются.
- «Стоп» блокируется только по скорости GPS, не по Bluetooth: при автозапуске магнитола может включиться и телефон подключится к ней, а заглушить прогреваемый двигатель нужно и сидя в машине.
- Если ни GPS, ни Bluetooth не дают сведений (в том числе когда Bluetooth телефона выключен), критичная команда требует отметить «Машина стоит».
- Все проверки (версия ПО, пароль, движение, Bluetooth, ПИН) повторяются в момент отправки — не только в окне команды, но и в самом модуле отправки.
- **Антиограбление в движении** — только аварийно: ПИН и удержание 5 секунд.
- **Выключение антиограбления** (`1000` + PW) доступно всегда, в том числе в движении. Нужен пароль PW в профиле.
- Ослабить защиту (выключить GPS/Bluetooth-контроль, поднять порог скорости, сменить или удалить ПИН, включить вход по отпечатку, выключить подтверждение команд на виджете) можно только на стоянке и через ПИН.
- Новый профиль — это новый номер сигнализации, поэтому добавить его можно только на стоянке и через ПИН (если ПИН задан).

### Профили машин
В профиле:
- номер SIM сигнализации и SIM телефона для отправки;
- пароль PW (зашифрован ключом Android Keystore) и режим отправки с паролем;
- символ «#» в конце SMS: авто (с ПО O7) / всегда / никогда;
- версия ЦБ (необязательно), Bluetooth машины, цены для оценки баланса;
- своя таблица команд.

Активный профиль выбирается на главном экране или в «Профилях машин» — с подтверждением, в движении недоступно.

**Формат с паролем** (номера M2–M4 или включённый 00961): код, затем `00`, затем PW. Например: `10001234`, `0100123405#`. Команды, для которых формат с паролем не описан, в этом режиме недоступны.

### Таблица команд (JSON)
Таблица по умолчанию — `app/src/main/assets/commands_default.json`; профилю можно задать свою. Редактор, проверка, импорт и экспорт — в приложении (правка — через «Критичное»).

Поля:
- `code`, `name`, `group`;
- `dangerous` — опасная, `critical` — критичная;
- `minFw` — минимальная версия ПО модуля, `cbRequirement` — требование к ЦБ, `notApplicable` — причина неприменимости;
- `verified` — проверена на машине;
- `template`, `params` (`key`, `label`, `type`: INT/PHONE, `min`, `max`, `width`, `default`);
- `m1Only`, `control`, `hashAllowed`, `note`, `source`;
- `kind`: NORMAL / STATUS / USSD_BALANCE / FIRMWARE_UPDATE / ANTIHIJACK_OFF.

В `template` можно использовать подстановки:
- `{PW}` — «00» + пароль, только в режиме пароля;
- `{PWRAW}` — пароль всегда;
- `{USSD}` — запрос баланса из профиля;
- `{КЛЮЧ}` — параметр из `params`.

Программирования таблиц центрального блока (`0018…`) в приложении нет намеренно: ошибка в функции №2 (тип КПП, программная нейтраль) опасна на механике.

### Виджет
- 2–4 кнопки (выбор — в настройках) и последний статус со временем.
- Опасные и критичные команды на виджет не ставятся и с него не отправляются. «Стоп» — тоже: вне приложения не определить, едет ли машина.
- Управляющие команды по умолчанию идут через окно подтверждения.
- Одна и та же команда с виджета уходит не чаще раза в 5 секунд — двойное нажатие не отправит две SMS.
- Виджет сам обновляется при смене профиля, эмулятора и набора кнопок.

### Счётчик SMS
Части SMS, отправленные с телефона, за день и за месяц. При достижении лимита — уведомление.

### Отладка без машины
Эмулятор ответов по образцам из ТЗ и документации. Режимы: успех, неудача, нет ответа, склеенный текст. Задержка ответа настраивается. Эмулируется обновление ПО (версия после — в настройках) и входящее без команды. Данные эмуляции помечены и удаляются одной кнопкой. Там же — проверка разбора любого текста SMS.

Структура:
- `core/` — чистая логика без Android: разбор ответов, версии, сборка текста команд, CSV, баланс, правила доступности, эмулятор, JSON-таблица;
- `data/` — Room, настройки, шифрование пароля, экспорт журнала;
- `sms/` — отправка, приём, отчёты, тайм-ауты, досканирование входящих;
- `engine/` — привязка ответов, сеанс обновления, уведомления;
- `safety/` — движение (GPS, Bluetooth), ПИН, отпечаток;
- `widget/` — виджет;
- `ui/` — экраны.

Модульные тесты: `.\gradlew.bat testDebugUnitTest` (Windows) или `./gradlew testDebugUnitTest`.
